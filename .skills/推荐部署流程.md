# VIRS 推荐部署流程

> 适用于云服务器 ECS（Ubuntu 22.04+）从 0 到 1 部署 VIRS 交易系统
> 最后修订: 2026-07-01

---

## 1. Docker 配置文件分析

### 1.1 端口映射总览

项目通过 [docker-compose.yml](file:///docker-compose.yml) 编排两个服务，端口映射关系如下：

| 服务 | 容器内端口 | 宿主机端口 | 映射规则 | 是否对外暴露 |
|------|-----------|-----------|---------|-------------|
| `virs-backend` | 8080 | 8080 | `${BACKEND_PORT:-8080}:8080` | ✅ **必须开放**（前端 + API + WebSocket） |
| `virs-postgres` | 5432 | 5432 | `${POSTGRES_PORT:-5432}:5432` | ❌ **不应开放**（仅内部 Docker 网络访问） |

### 1.2 外人访问哪个端口？

**外人只需要访问宿主机的 `8080` 端口**。

原因：[Dockerfile](file:///Dockerfile) 第 4 阶段（runtime）把前端静态文件 `/app/frontend/dist` 和后端二进制 `/app/virs` 打包到同一个镜像里，后端 Axum 路由通过 fallback 机制：
- `/api/*` → 走后端 API
- `/ws/*` → WebSocket 推送
- 其他路径 → 返回前端 `index.html`（单页应用）

所以浏览器只需访问 `http://ECS公网IP:8080/` 即可获得前端页面 + 后端 API + WebSocket 推送，**不需要单独部署 Nginx 或开多个端口**。

### 1.3 PostgreSQL 数据库

- 容器内端口 5432，映射到宿主机 5432
- **生产环境建议不映射到宿主机**（修改 docker-compose.yml 删除 `ports` 段），只让 backend 通过 Docker 内部网络 `postgres:5432` 访问
- 如果需要在宿主机用 `psql` 连接调试，可以临时开放，调试完关闭

### 1.5 多阶段构建流程

[Dockerfile](file:///Dockerfile) 采用 4 阶段构建，最终镜像约 50-80 MB：

| 阶段 | 基础镜像 | 作用 |
|------|---------|------|
| Stage 1 | `node:20-alpine` | 编译前端（`npm ci` → `npm run build` → `dist/`） |
| Stage 2 | `rust:slim-bookworm` | `cargo chef prepare` 生成依赖 recipe |
| Stage 3 | `rust:slm-bookworm` | `cargo chef cook` + `cargo build --release` 编译 Rust |
| Stage 4 | `gcr.io/distroless/cc-debian12:nonroot` | 运行时镜像（无 shell、无包管理器，最小化攻击面） |

最终镜像内容：
- `/app/virs` — Rust 二进制
- `/app/frontend/dist/` — 前端静态文件
- `/app/migrations/init.sql` — 数据库迁移
- `/app/strategies/` — LLM 策略模板

## 2. 完整部署步骤（从 0 到 1）

### 2.1 准备 ECS 实例

**推荐配置：**

| 项 | 推荐值 | 说明 |
|----|--------|------|
| 操作系统 | Ubuntu 22.04 LTS | 长期支持版 |
| CPU | 2 核 | 业务量小够用 |
| 内存 | 4 GB | PostgreSQL + Rust 后端 |
| 系统盘 | 40 GB SSD | OS + Docker + 镜像 + 数据库数据 + 日志 |
| 公网带宽 | 按量付费 5 Mbps | 起步够用，后续可升级 |
| 安全组入方向 | 开放 22, 8080 端口 | SSH + 应用访问 |

**安全组规则配置（云控制台）：**

| 协议 | 端口 | 来源 | 用途 |
|------|------|------|------|
| TCP | 22 | 你的 IP/32 | SSH 管理（限 IP 更安全） |
| TCP | 8080 | 0.0.0.0/0 | VIRS 应用访问 |
| TCP | 443 | 0.0.0.0/0 | （可选）HTTPS，配 Nginx 后用 |

**不要开放 5432 端口**（PostgreSQL 仅 Docker 内网访问）。

### 2.2 SSH 连接 ECS

```bash
ssh root@YOUR_ECS_IP
```

### 2.3 安装 Docker + Docker Compose

```bash
# 一键安装 Docker（官方脚本）
curl -fsSL https://get.docker.com | sh

# 启动 Docker 服务
sudo systemctl enable --now docker

# 把当前用户加入 docker 组（免 sudo）
sudo usermod -aG docker $USER

# 重新登录让组权限生效
exit
ssh root@YOUR_ECS_IP

# 验证安装
docker --version
docker compose version
```

**国内 ECS 加速器配置（拉取镜像慢时配置）：**

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}
EOF
sudo systemctl restart docker
```

### 2.4 从本地上传源码到 ECS

**在本地 macOS 执行（关键：`COPYFILE_DISABLE=1` 避免 macOS 元数据污染）：**

```bash
cd /Users/ruimve/Documents/virs/virs

# 打包源码（排除编译产物）
COPYFILE_DISABLE=1 tar --exclude='target' \
    --exclude='.git' \
    --exclude='frontend/node_modules' \
    --exclude='frontend/dist' \
    --exclude='.trae-cn' \
    -czf virs-deploy.tar.gz .

# 验证 tar 包内无 macOS 元数据文件（应该无输出）
tar -tzf virs-deploy.tar.gz | grep '\._'

# 上传到 ECS
scp virs-deploy.tar.gz root@YOUR_ECS_IP:/opt/
```

**在 ECS 上执行：**

```bash
# 解压源码
cd /opt
mkdir -p virs && tar -xzf virs-deploy.tar.gz -C virs
cd virs

# 清理可能残留的 macOS 元数据文件（兜底）
find . -name "._*" -type f -delete
```

### 2.5 配置环境变量（关键步骤）

```bash
cd /opt/virs
cp .env.example .env
```

**生成强随机密钥：**

```bash
# 生成 3 个不同的密钥
openssl rand -hex 32  # → 填入 ENCRYPTION_KEY
openssl rand -hex 32  # → 填入 LLM_KEY（必须与 ENCRYPTION_KEY 不同）
openssl rand -hex 16  # → 填入 JWT_SECRET
```

**编辑 `.env` 文件：**

```bash
nano .env
```

**必须修改的字段（不改会拒绝启动）：**

| 字段 | 说明 | 示例 |
|------|------|------|
| `ENCRYPTION_KEY` | 64 位随机 hex，加密交易所 API 凭证 | `a1b2c3...(64位)` |
| `LLM_KEY` | 64 位随机 hex，**必须与 ENCRYPTION_KEY 不同** | `d4e5f6...(64位)` |
| `JWT_SECRET` | 32+ 字符，JWT 签名 | `g7h8i9...(32+位)` |
| `ADMIN_USERNAME` | 管理员用户名 | `admin` |
| `ADMIN_PASSWORD` | 至少 12 字符强密码 | `MyStr0ngP@ssw0rd` |
| `POSTGRES_PASSWORD` | 数据库密码，改为强密码 | `DbP@ssw0rd123` |
| `DATABASE_URL` | 更新密码与 POSTGRES_PASSWORD 一致 | `postgresql://virs:DbP@ssw0rd123@postgres:5432/virs` |

**国内 ECS 必填：**

```env
# 如果 ECS 在大陆，访问币安等交易所需要代理
PROXY_URL=socks5://代理地址:端口
```

### 2.6 构建并启动服务

```bash
cd /opt/virs

# 构建镜像并启动（首次需要 10-30 分钟编译 Rust）
docker compose up -d --build

# 查看容器状态
docker compose ps

# 查看后端启动日志（确认无错误）
docker compose logs -f backend --tail 100
```

**首次构建说明：**
- Rust 编译耗时较长（10-30 分钟），后续修改代码后增量编译只需 1-3 分钟
- 编译期间会占用约 2-4 GB 内存，ECS 内存不足会 OOM，建议 swap 一下：

```bash
# 创建 4GB swap（内存不足时启用）
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 2.7 验证部署成功

```bash
# 1. 健康检查（应返回 {"status":"ok"} 之类）
curl http://localhost:8080/api/health

# 2. 浏览器访问（替换为你的 ECS 公网 IP）
# http://YOUR_ECS_IP:8080/

# 3. 登录系统
# 用户名：.env 里的 ADMIN_USERNAME
# 密码：.env 里的 ADMIN_PASSWORD
```

### 2.8 （推荐）配置 Nginx + HTTPS

直接暴露 8080 不安全，建议加 Nginx 反向代理 + HTTPS 证书：

```bash
# 安装 Nginx + Certbot
sudo apt install -y nginx certbot python3-certbot-nginx

# 配置反向代理
sudo tee /etc/nginx/conf.d/virs.conf <<'EOF'
server {
    listen 80;
    server_name your-domain.com;  # 替换为你的域名

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket 支持（/ws 路径）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400;
    }
}
EOF

sudo nginx -t && sudo systemctl reload nginx

# 申请 HTTPS 证书（需要域名已解析到 ECS IP）
sudo certbot --nginx -d your-domain.com
```

**配置 Nginx 后的安全组调整：**

| 协议 | 端口 | 来源 | 用途 |
|------|------|------|------|
| TCP | 22 | 你的 IP/32 | SSH |
| TCP | 80 | 0.0.0.0/0 | HTTP（重定向到 HTTPS） |
| TCP | 443 | 0.0.0.0/0 | HTTPS |
| ~~TCP~~ | ~~8080~~ | ~~0.0.0.0/0~~ | ❌ **关闭**（已由 Nginx 代理） |

然后修改 [docker-compose.yml](file:///docker-compose.yml) 第 77 行，让 backend 只监听本地：

```yaml
ports:
  - "127.0.0.1:8080:8080"  # 只监听本地，由 Nginx 反向代理
```

重启服务：

```bash
cd /opt/virs
docker compose up -d
```

访问 `https://your-domain.com/` 即可。

## 3. 常用运维命令

```bash
cd /opt/virs

# 查看服务状态
docker compose ps

# 查看实时日志
docker compose logs -f backend --tail 100

# 重启后端
docker compose restart backend

# 升级版本（重新上传代码后）
docker compose build backend && docker compose up -d backend

# 进入容器调试（distroless 无 shell，只能用 exec）
docker compose exec backend /app/virs --version  # 示例，实际无 shell

# 备份 PostgreSQL
docker exec virs-postgres pg_dump -U virs virs > backup_$(date +%Y%m%d).sql

# 恢复 PostgreSQL
docker exec -i virs-postgres psql -U virs virs < backup_20260701.sql

# 停止所有服务
docker compose down

# 停止并删除数据卷（⚠️ 会丢失数据库数据）
docker compose down -v
```

## 4. 故障排查

### 4.1 容器启动失败

```bash
# 查看日志
docker compose logs backend
docker compose logs postgres

# 常见错误：
# - "ENCRYPTION_KEY is required" → .env 没配置
# - "ADMIN_PASSWORD is required" → .env 没配置
# - "ENCRYPTION_KEY must differ from LLM_KEY" → 两个密钥设成一样的了
# - 数据库连接失败 → 检查 DATABASE_URL 里的密码与 POSTGRES_PASSWORD 一致
```

### 4.2 外部无法访问 8080

```bash
# 1. 容器是否运行
docker compose ps

# 2. 本地能否访问
curl http://127.0.0.1:8080/api/health

# 3. 防火墙是否放行
sudo ufw status
sudo iptables -L -n | grep 8080

# 4. 云控制台安全组是否放行 8080（最常见原因）
```

### 4.3 构建时内存不足（OOM）

```bash
# 查看内存
free -h

# 创建 swap（见 2.6 节）

# 或限制 Rust 编译并行度
# 修改 Dockerfile，在 cargo build 前加：
# ENV CARGO_BUILD_JOBS=1
```

### 4.4 前端构建报 `._*` 文件错误

macOS 打包时没加 `COPYFILE_DISABLE=1` 导致。解决：

```bash
# ECS 上清理
find /opt/virs -name "._*" -type f -delete

# 重新打包（本地）
COPYFILE_DISABLE=1 tar ... -czf virs-deploy.tar.gz .
```

### 4.5 数据库迁移失败

```bash
# 查看数据库状态
docker compose exec postgres pg_isready -U virs

# 手动执行迁移
docker compose exec backend /app/virs  # 启动时会自动执行 migrations/init.sql

# 查看表
docker exec -it virs-postgres psql -U virs -d virs -c "\dt"
```

## 7. 一键部署脚本（可选）

把以下脚本保存为 `deploy.sh`，在 ECS 上执行：

```bash
#!/bin/bash
set -e

DEPLOY_DIR="/opt/virs"
ECS_IP=$(curl -s ifconfig.me)

echo "===== VIRS 一键部署脚本 ====="

# 1. 检查 Docker
if ! command -v docker &> /dev/null; then
    echo "安装 Docker..."
    curl -fsSL https://get.docker.com | sh
    systemctl enable --now docker
fi

# 2. 创建 swap（内存 < 4G 时）
if [ "$(free -g | awk '/^Mem:/{print $2}')" -lt 4 ]; then
    if ! swapon --show | grep -q swapfile; then
        echo "创建 4GB swap..."
        fallocate -l 4G /swapfile
        chmod 600 /swapfile
        mkswap /swapfile
        swapon /swapfile
        echo '/swapfile none swap sw 0 0' >> /etc/fstab
    fi
fi

# 3. 进入部署目录
cd $DEPLOY_DIR

# 4. 检查 .env
if [ ! -f .env ]; then
    cp .env.example .env
    echo "⚠️  请编辑 $DEPLOY_DIR/.env 配置密钥后再运行："
    echo "   nano $DEPLOY_DIR/.env"
    echo "   必填项：ENCRYPTION_KEY, LLM_KEY, JWT_SECRET, ADMIN_PASSWORD"
    exit 1
fi

# 5. 构建并启动
echo "开始构建（可能需要 10-30 分钟）..."
docker compose up -d --build

# 6. 等待启动
echo "等待后端启动..."
sleep 10

# 7. 健康检查
if curl -s http://localhost:8080/api/health | grep -q "ok"; then
    echo "✅ 部署成功！"
    echo "   访问地址：http://$ECS_IP:8080/"
    echo "   健康检查：http://$ECS_IP:8080/api/health"
else
    echo "❌ 健康检查失败，查看日志："
    echo "   docker compose logs backend"
fi
```

使用方法：

```bash
chmod +x deploy.sh
./deploy.sh
```
