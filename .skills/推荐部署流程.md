# VIRS 推荐部署流程

> 适用于云服务器 ECS（Ubuntu 22.04+）从 0 到 1 部署 VIRS 交易系统
> 最后修订: 2026-08-12

---

## 1. Docker 配置文件分析

### 1.1 端口映射总览

项目通过 [docker-compose.yml](file:///docker-compose.yml) 编排三个服务，端口映射关系如下：

| 服务 | 容器内端口 | 宿主机端口 | 映射规则 | 是否对外暴露 |
|------|-----------|-----------|---------|-------------|
| `virs-backend` | 8080 | 8080 | `127.0.0.1:${BACKEND_PORT:-8080}:8080` | ❌ **仅本地回环**（公网不可达） |
| `virs-postgres` | 5432 | 5432 | `127.0.0.1:${POSTGRES_PORT:-5432}:5432` | 🟢 **仅本地回环**（公网不可达） |
| `virs-cloudflared` | — | — | 无端口映射 | — 出站隧道，不监听任何端口 |

**关键设计**：backend 端口绑定到 `127.0.0.1`，公网无法直接访问；远程访问通过 **Cloudflare Tunnel**（出站隧道）实现，服务器**无需开放任何入站端口**。

### 1.2 外人如何访问？

外人通过 **Cloudflare 边缘节点的 443 端口**访问，流量经出站隧道反向回到服务器：

```
用户浏览器 ──HTTPS:443──▶ Cloudflare 边缘 ──出站隧道──▶ cloudflared 容器 ──▶ backend:8080(Docker内网)
```

- 浏览器访问 `https://你的域名/` 即可获得前端页面 + 后端 API + WebSocket 推送
- 服务器**无需开放 80/443/8080 任何入站端口**，安全组只需保留 22(SSH)
- 无需 Nginx、无需 Certbot、无需证书管理（Cloudflare 边缘自动处理 HTTPS）

原因：[Dockerfile](file:///Dockerfile) 把前端静态文件 `/app/frontend/dist` 和后端二进制 `/app/virs` 打包到同一镜像，Axum 路由通过 fallback 机制：
- `/api/*` → 走后端 API
- `/ws/*` → WebSocket 推送
- 其他路径 → 返回前端 `index.html`（单页应用）

cloudflared 与 backend 同处 `virs-net` Docker 网络，通过内网域名 `backend:8080` 回源，单一入口覆盖前端 + API + WebSocket，**不需要单独部署 Nginx 或开多个端口**。

### 1.3 PostgreSQL 数据库

- 容器内端口 5432，映射到宿主机 `127.0.0.1:5432`（仅本地回环，公网不可达）
- backend 通过 Docker 内部网络 `postgres:5432` 访问，不经过宿主机端口映射
- 本地调试：`docker exec -it virs-postgres psql -U virs -d virs`，或 GUI 工具连 `127.0.0.1:5432`

### 1.4 Docker 网络架构

```
┌───────────────────────────────────────────────────┐
│              ECS 宿主机                            │
│                                                   │
│  ┌───────────────────────────────────────────┐    │
│  │      Docker 网络: virs-net                │    │
│  │                                           │    │
│  │  ┌──────────────┐    ┌────────────────┐   │    │
│  │  │ virs-backend │◀───│ virs-cloudflared│  │    │
│  │  │   :8080      │    │  (隧道客户端)    │  │    │
│  │  └──────┬───────┘    └───────┬────────┘   │    │
│  │         │ postgres:5432      │ 出站连接    │    │
│  │         ▼                    │            │    │
│  │  ┌──────────────┐            │            │    │
│  │  │ virs-postgres│            │            │    │
│  │  │   :5432      │            │            │    │
│  │  └──────────────┘            │            │    │
│  └──────────────────────────────┼────────────┘    │
│         │ 127.0.0.1:8080         │（出站）         │
│         │ （仅本地调试）          │                 │
└─────────┼────────────────────────┼─────────────────┘
          │ 无入站端口（零暴露）    │
          │                        │ 公网
          │                        ▼
          │                ┌──────────────────┐
          │         ┌──────│ Cloudflare 边缘   │
          │         │      │ (橙云+TLS:443)   │
          │         │      └────────┬─────────┘
   ┌──────▼──────┐            HTTPS │ :443
   │ 本地调试curl │◀───请求沿隧道回传─┘
   └─────────────┘
```

> **原理**：cloudflared 主动向 Cloudflare 边缘发起出站长连接（防火墙默认放行出站），用户的 HTTPS 请求到达边缘后，沿这条已建立的隧道反向流回 backend。服务器公网 IP 上**无任何监听端口**，这是 Tunnel 相比传统反向代理最核心的安全优势。

### 1.5 多阶段构建流程

[Dockerfile](file:///Dockerfile) 采用 4 阶段构建，最终镜像约 50-80 MB：

| 阶段 | 基础镜像 | 作用 |
|------|---------|------|
| Stage 1 | `node:20-alpine` | 编译前端（`npm ci` → `npm run build` → `dist/`） |
| Stage 2 | `rust:slim-bookworm` | `cargo chef prepare` 生成依赖 recipe |
| Stage 3 | `rust:slm-bookworm` | `cargo chef cook` + `cargo build --release` 编译 Rust |
| Stage 4 | `gcr.io/distroless/cc-debian12:nonroot` | 运行时镜像（无 shell、无包管理器，最小化攻击面） |

最终镜像内容：
- `/app/virs` — Rust 二进制
- `/app/frontend/dist/` — 前端静态文件
- `/app/migrations/init.sql` — 数据库迁移
- `/app/strategies/` — LLM 策略模板

## 2. 完整部署步骤（从 0 到 1）

### 2.1 准备 ECS 实例

**推荐配置：**

| 项 | 推荐值 | 说明 |
|----|--------|------|
| 操作系统 | Ubuntu 22.04 LTS | 长期支持版 |
| CPU | 2 核 | 业务量小够用 |
| 内存 | 4 GB | PostgreSQL + Rust 后端 |
| 系统盘 | 40 GB SSD | OS + Docker + 镜像 + 数据库数据 + 日志 |
| 公网带宽 | 按量付费 5 Mbps | 起步够用，后续可升级 |
| 安全组入方向 | 仅开放 22 端口 | SSH 管理（Tunnel 为出站，无需开 80/443/8080） |

**安全组规则配置（云控制台）：**

| 协议 | 端口 | 来源 | 用途 |
|------|------|------|------|
| TCP | 22 | 你的 IP/32 | SSH 管理（限 IP 更安全） |

**不需要开放 80/443/8080**：
- Cloudflare Tunnel 是出站连接，服务器零入站端口
- backend 绑定 `127.0.0.1:8080`，公网本就不可达
- 出站方向需能访问 Cloudflare 隧道端口（TCP 7844/443），云服务器默认放行全部出站，一般无需额外配置

### 2.2 SSH 连接 ECS

```bash
ssh root@YOUR_ECS_IP
```

### 2.3 安装 Docker + Docker Compose

```bash
# 一键安装 Docker（官方脚本）
curl -fsSL https://get.docker.com | sh

# 启动 Docker 服务
sudo systemctl enable --now docker

# 把当前用户加入 docker 组（免 sudo）
sudo usermod -aG docker $USER

# 重新登录让组权限生效
exit
ssh root@YOUR_ECS_IP

# 验证安装
docker --version
docker compose version
```

**国内 ECS 加速器配置（拉取镜像慢时配置）：**

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}
EOF
sudo systemctl restart docker
```

### 2.4 从本地上传源码到 ECS

**在本地 macOS 执行（关键：`COPYFILE_DISABLE=1` 避免 macOS 元数据污染）：**

```bash
cd /Users/ruimve/Documents/virs/virs

# 打包源码（排除编译产物）
COPYFILE_DISABLE=1 tar --exclude='target' \
    --exclude='.git' \
    --exclude='frontend/node_modules' \
    --exclude='frontend/dist' \
    --exclude='.trae-cn' \
    -czf virs-deploy.tar.gz .

# 验证 tar 包内无 macOS 元数据文件（应该无输出）
tar -tzf virs-deploy.tar.gz | grep '\._'

# 上传到 ECS
scp virs-deploy.tar.gz root@YOUR_ECS_IP:/opt/
```

**在 ECS 上执行：**

```bash
# 解压源码
cd /opt
mkdir -p virs && tar -xzf virs-deploy.tar.gz -C virs
cd virs

# 清理可能残留的 macOS 元数据文件（兜底）
find . -name "._*" -type f -delete
```

### 2.5 配置环境变量（关键步骤）

```bash
cd /opt/virs
install -m 600 .env.example .env
```

**生成强随机密钥：**

```bash
# 生成 3 个不同的密钥
openssl rand -hex 32  # → 填入 ENCRYPTION_KEY
openssl rand -hex 32  # → 填入 LLM_KEY（必须与 ENCRYPTION_KEY 不同）
openssl rand -hex 16  # → 填入 JWT_SECRET
```

**编辑 `.env` 文件：**

```bash
nano .env
```

**必须修改的字段（不改会拒绝启动）：**

| 字段 | 说明 | 示例 |
|------|------|------|
| `ENCRYPTION_KEY` | 64 位随机 hex，加密交易所 API 凭证 | `a1b2c3...(64位)` |
| `LLM_KEY` | 64 位随机 hex，**必须与 ENCRYPTION_KEY 不同** | `d4e5f6...(64位)` |
| `JWT_SECRET` | 32+ 字符，JWT 签名 | `g7h8i9...(32+位)` |
| `ADMIN_USERNAME` | 管理员用户名 | `admin` |
| `ADMIN_PASSWORD` | 至少 12 字符强密码 | `MyStr0ngP@ssw0rd` |
| `POSTGRES_PASSWORD` | 数据库密码，改为强密码 | `DbP@ssw0rd123` |
| `DATABASE_URL` | 更新密码与 POSTGRES_PASSWORD 一致 | `postgresql://virs:DbP@ssw0rd123@postgres:5432/virs` |

**远程访问（Cloudflare Tunnel，生产环境必填）：**

```env
# 从 Cloudflare Zero Trust 控制台获取（见 2.8 节）
CLOUDFLARE_TUNNEL_TOKEN=eyJh...你的token...
```

**国内 ECS 必填：**

```env
# 如果 ECS 在大陆，访问币安等交易所需要代理
PROXY_URL=socks5://代理地址:端口
```

### 2.6 构建并启动服务

```bash
cd /opt/virs

# 构建镜像并启动（含隧道，首次需要 10-30 分钟编译 Rust）
docker compose --profile tunnel up -d --build

# 查看容器状态（应有 postgres + backend + cloudflared 三个）
docker compose ps

# 查看 cloudflared 隧道连接日志（看到 "Registered tunnel connection" 即成功）
docker compose logs -f cloudflared --tail 100
```

> **本地开发模式**（无需隧道、无需 token）：`docker compose up -d`（不加 `--profile tunnel`），只起 postgres + backend，访问 `http://localhost:8080`。cloudflared 服务挂在 `tunnel` profile 下，不激活则不启动。

**首次构建说明：**
- Rust 编译耗时较长（10-30 分钟），后续修改代码后增量编译只需 1-3 分钟
- 编译期间会占用约 2-4 GB 内存，ECS 内存不足会 OOM，建议 swap 一下：

```bash
# 创建 4GB swap（内存不足时启用）
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 2.7 验证部署成功

```bash
# 1. 本地健康检查（应返回 {"status":"ok"} 之类）
curl http://127.0.0.1:8080/api/health

# 2. 公网访问（替换为你的域名，需先完成 2.8 隧道配置）
# https://你的域名/

# 3. 登录系统
# 用户名：.env 里的 ADMIN_USERNAME
# 密码：.env 里的 ADMIN_PASSWORD
```

### 2.8 配置 Cloudflare Tunnel（远程 HTTPS 访问）

backend 绑定 `127.0.0.1:8080`，公网无法直达。通过 Cloudflare Tunnel 暴露为 HTTPS 域名——**免费、零入站端口、自动证书**，替代传统的 Nginx + Certbot 方案。

**步骤 1：创建隧道并获取 Token**

1. 登录 [Cloudflare Zero Trust](https://one.dash.cloudflare.com/) 控制台
2. Networks → Tunnels → Create a tunnel → 选 `Cloudflared` 类型
3. 命名隧道，创建后复制 **Tunnel Token**（形如 `eyJh...` 的长字符串）
4. 将 Token 填入 `.env`：`CLOUDFLARE_TUNNEL_TOKEN=eyJh...`

> Tunnel 属于 Cloudflare Zero Trust 免费档，50 用户内零成本，不限连接数、不限流量。本项目仅单管理员，永久免费。

**步骤 2：配置 Public Hostname（回源路由）**

在隧道的 Public Hostname 页加一条：

| 字段 | 值 |
|------|------|
| Subdomain | `virs`（或任意子域名） |
| Domain | `你的域名.com`（须托管在 Cloudflare DNS） |
| Type | `HTTP` |
| URL | `backend:8080`（Docker 内网域名，**不是 localhost**） |

> cloudflared 与 backend 同在 `virs-net` 网络，通过 Docker DNS 解析 `backend`。Cloudflare 边缘自动提供 443 HTTPS + 橙云代理 + DDoS 防护，DNS 的 CNAME 记录由隧道自动生成，无需手动配置。

**步骤 3：启动并验证隧道**

```bash
cd /opt/virs
docker compose --profile tunnel up -d
docker compose logs cloudflared | grep "Registered tunnel connection"
# 看到 4 条 "Registered tunnel connection" 即隧道建立成功
```

访问 `https://virs.你的域名.com/` 即可。

**步骤 4：确认安全组（无需开放 80/443）**

| 协议 | 端口 | 来源 | 用途 |
|------|------|------|------|
| TCP | 22 | 你的 IP/32 | SSH |
| ~~80/443/8080~~ | — | — | ❌ 均无需开放 |

## 3. 常用运维命令

```bash
cd /opt/virs

# ---- 生命周期 ----
docker compose --profile tunnel up -d        # 启动含隧道
docker compose --profile tunnel down         # 停止含隧道
docker compose up -d                         # 本地开发模式（无隧道）

# ---- 状态与日志 ----
docker compose ps
docker compose logs -f backend --tail 100
docker compose logs -f cloudflared           # 隧道连接日志
docker compose restart cloudflared           # 重启隧道客户端

# ---- 升级 ----
docker compose --profile tunnel build backend && docker compose --profile tunnel up -d backend

# ---- 数据库 ----
docker exec virs-postgres pg_dump -U virs virs > backup_$(date +%Y%m%d).sql
docker exec -i virs-postgres psql -U virs virs < backup_20260812.sql

# ---- 清理 ----
docker compose --profile tunnel down         # 停止所有服务
docker compose --profile tunnel down -v      # ⚠️ 停止并删除数据卷（丢数据库）
```

> 注：使用 `--profile tunnel` 时，`down` 也会停止 cloudflared。本地开发不带该参数即可。

## 4. 故障排查

### 4.1 容器启动失败

```bash
# 查看日志
docker compose logs backend
docker compose logs postgres

# 常见错误：
# - "ENCRYPTION_KEY is required" → .env 没配置
# - "ADMIN_PASSWORD is required" → .env 没配置
# - "ENCRYPTION_KEY must differ from LLM_KEY" → 两个密钥设成一样的了
# - 数据库连接失败 → 检查 DATABASE_URL 里的密码与 POSTGRES_PASSWORD 一致
```

### 4.2 cloudflared 隧道连不上 / 域名无法访问

```bash
# 查看隧道日志
docker compose logs cloudflared

# 常见错误：
# - "error validating token" → CLOUDFLARE_TUNNEL_TOKEN 未填或填错
# - 长时间无 "Registered tunnel connection" → ECS 出站被限，确认能出站到 TCP 7844/443
# - 域名访问返回 502 → Public Hostname 的 URL 应填 backend:8080（Docker 内网），不是 localhost
# - 域名访问返回 1033 → 隧道未连接，检查 cloudflared 是否在运行
# - 容器列表没有 cloudflared → 启动时漏了 --profile tunnel 参数
```

### 4.3 本地能访问、公网不能访问

```bash
# 1. 本地健康检查（应返回 ok）
curl http://127.0.0.1:8080/api/health

# 2. cloudflared 是否运行
docker compose ps cloudflared

# 3. 隧道是否注册成功
docker compose logs cloudflared | grep "Registered tunnel connection"

# 4. Cloudflare 控制台 Public Hostname 是否指向 backend:8080
```

### 4.4 构建时内存不足（OOM）

```bash
# 查看内存
free -h

# 创建 swap（见 2.6 节）

# 或限制 Rust 编译并行度
# 修改 Dockerfile，在 cargo build 前加：
# ENV CARGO_BUILD_JOBS=1
```

### 4.5 前端构建报 `._*` 文件错误

macOS 打包时没加 `COPYFILE_DISABLE=1` 导致。解决：

```bash
# ECS 上清理
find /opt/virs -name "._*" -type f -delete

# 重新打包（本地）
COPYFILE_DISABLE=1 tar ... -czf virs-deploy.tar.gz .
```

### 4.6 数据库迁移失败

```bash
# 查看数据库状态
docker compose exec postgres pg_isready -U virs

# 手动执行迁移
docker compose exec backend /app/virs  # 启动时会自动执行 migrations/init.sql

# 查看表
docker exec -it virs-postgres psql -U virs -d virs -c "\dt"
```

## 7. 一键部署脚本（可选）

把以下脚本保存为 `deploy.sh`，在 ECS 上执行：

```bash
#!/bin/bash
set -e

DEPLOY_DIR="/opt/virs"
ECS_IP=$(curl -s ifconfig.me)

echo "===== VIRS 一键部署脚本 ====="

# 1. 检查 Docker
if ! command -v docker &> /dev/null; then
    echo "安装 Docker..."
    curl -fsSL https://get.docker.com | sh
    systemctl enable --now docker
fi

# 2. 创建 swap（内存 < 4G 时）
if [ "$(free -g | awk '/^Mem:/{print $2}')" -lt 4 ]; then
    if ! swapon --show | grep -q swapfile; then
        echo "创建 4GB swap..."
        fallocate -l 4G /swapfile
        chmod 600 /swapfile
        mkswap /swapfile
        swapon /swapfile
        echo '/swapfile none swap sw 0 0' >> /etc/fstab
    fi
fi

# 3. 进入部署目录
cd $DEPLOY_DIR

# 4. 检查 .env
if [ ! -f .env ]; then
    install -m 600 .env.example .env
    echo "⚠️  请编辑 $DEPLOY_DIR/.env 配置密钥后再运行："
    echo "   nano $DEPLOY_DIR/.env"
    echo "   必填项：ENCRYPTION_KEY, LLM_KEY, JWT_SECRET, ADMIN_PASSWORD"
    echo "   隧道项：CLOUDFLARE_TUNNEL_TOKEN（见部署文档 2.8 节）"
    exit 1
fi

# 5. 构建并启动（含 Cloudflare Tunnel）
echo "开始构建（可能需要 10-30 分钟）..."
docker compose --profile tunnel up -d --build

# 6. 等待启动
echo "等待后端启动..."
sleep 10

# 7. 健康检查（本地回环）
if curl -s http://127.0.0.1:8080/api/health | grep -q "ok"; then
    echo "✅ 部署成功！"
    echo "   本地健康检查：http://127.0.0.1:8080/api/health"
    echo "   公网访问：请完成 Cloudflare Tunnel 配置后访问 https://你的域名/"
    echo "   隧道日志：docker compose logs cloudflared"
else
    echo "❌ 健康检查失败，查看日志："
    echo "   docker compose logs backend"
fi
```
