# VIRS 推荐部署流程

> 适用于云服务器 ECS（Ubuntu 22.04+）从 0 到 1 部署 VIRS 交易系统
> 最后修订: 2026-08-13

---

## 1. 架构概述

三容器架构，零入站端口设计：

| 服务 | 镜像 | 容器端口 | 宿主机绑定 | 对外暴露 |
|------|------|---------|-----------|---------|
| virs-backend | 自构建（distroless） | 8080 | `127.0.0.1:8080` | 仅本地回环 |
| virs-postgres | `postgres:16-alpine` | 5432 | `127.0.0.1:5432` | 仅本地回环 |
| virs-cloudflared | `cloudflare/cloudflared` | — | — | 出站隧道，不监听端口 |

**远程访问原理**：用户浏览器 → Cloudflare 边缘（HTTPS 443）→ 出站隧道 → cloudflared 容器 → backend:8080（Docker 内网）。服务器**无需开放任何入站端口**，安全组只需保留 22（SSH）。

**单镜像设计**：Dockerfile 4 阶段构建（前端编译 → cargo chef 依赖缓存 → Rust 编译 → distroless 运行时），最终镜像约 50-80 MB，包含 Rust 二进制、前端静态文件、数据库迁移、策略模板。Axum 路由通过 fallback 机制统一入口：`/api/*` 走后端 API，`/ws/*` 走 WebSocket，其他路径返回前端 `index.html`。

**本地开发模式**：`docker compose up -d`（不加 `--profile tunnel`），只起 postgres + backend，访问 `http://localhost:8080`。

## 2. 前置准备

### 2.1 ECS 实例要求

| 项 | 推荐值 | 说明 |
|----|--------|------|
| 操作系统 | Ubuntu 22.04 LTS | 长期支持版 |
| CPU | 2 核 | 业务量小够用 |
| 内存 | 4 GB | PostgreSQL + Rust 编译 |
| 系统盘 | 40 GB SSD | OS + Docker + 镜像 + 数据 |
| 公网带宽 | 按量付费 5 Mbps | 起步够用，后续可升级 |

安全组入方向规则（云控制台配置）：

| 协议 | 端口 | 来源 | 用途 |
|------|------|------|------|
| TCP | 22 | 你的 IP/32 | SSH 管理 |

> Cloudflare Tunnel 是出站连接，无需开放 80/443/8080/5432。出站方向需能访问 Cloudflare 隧道端口（TCP 7844/443），云服务器默认放行全部出站，一般无需额外配置。

### 2.2 SSH 连接

```bash
ssh root@YOUR_ECS_IP
```

## 3. 部署步骤

### 3.1 安装 Docker

```bash
/* 一键安装 Docker */
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

/* 加入 docker 组免 sudo */
sudo usermod -aG docker $USER
exit

/* 重新登录让组权限生效，验证安装 */
ssh root@YOUR_ECS_IP
docker --version && docker compose version
```

国内 ECS 拉取镜像慢时配置加速器：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}
EOF
sudo systemctl restart docker
```

### 3.2 上传源码

**本地执行**（替换 `YOUR_ECS_IP` 和源码路径）：

```bash
cd /path/to/virs

/* 打包源码（排除编译产物，COPYFILE_DISABLE 防止 macOS 元数据污染） */
COPYFILE_DISABLE=1 tar --exclude='target' \
    --exclude='.git' \
    --exclude='frontend/node_modules' \
    --exclude='frontend/dist' \
    --exclude='.trae-cn' \
    -czf virs-deploy.tar.gz .

/* 验证 tar 包内无 macOS 元数据文件（应无输出） */
tar -tzf virs-deploy.tar.gz | grep '\._'

/* 上传到 ECS */
scp virs-deploy.tar.gz root@YOUR_ECS_IP:/opt/
```

**ECS 上执行**：

```bash
cd /opt
mkdir -p virs && tar -xzf virs-deploy.tar.gz -C virs
cd virs

/* 清理可能残留的 macOS 元数据文件（兜底） */
find . -name "._*" -type f -delete
```

### 3.3 配置环境变量

```bash
cd /opt/virs
install -m 600 .env.example .env

/* 生成强随机密钥 */
openssl rand -hex 32  /* → ENCRYPTION_KEY */
openssl rand -hex 32  /* → LLM_KEY（必须与 ENCRYPTION_KEY 不同） */
openssl rand -hex 16  /* → JWT_SECRET */

nano .env
```

**必须修改的字段（不改会拒绝启动）：**

| 字段 | 分类 | 说明 |
|------|------|------|
| `ENCRYPTION_KEY` | 必填-密钥 | 64 位随机 hex，加密交易所 API 凭证 |
| `LLM_KEY` | 必填-密钥 | 64 位随机 hex，**必须与 ENCRYPTION_KEY 不同** |
| `JWT_SECRET` | 必填-密钥 | 32+ 字符，JWT 签名 |
| `ADMIN_USERNAME` | 必填-连接 | 管理员用户名 |
| `ADMIN_PASSWORD` | 必填-连接 | 至少 12 字符强密码 |
| `POSTGRES_PASSWORD` | 仅 Docker | 数据库密码，改为强密码 |
| `CLOUDFLARE_TUNNEL_TOKEN` | 可选-隧道 | Cloudflare 隧道 Token（见 3.6 节） |
| `PROXY_URL` | 可选-基础设施 | 国内 ECS 访问交易所需要代理，如 `socks5://地址:端口` |

> **DATABASE_URL 无需手动修改** — docker-compose.yml 会从 `POSTGRES_USER`/`POSTGRES_PASSWORD`/`POSTGRES_DB` 自动拼接。`.env` 中的 `DATABASE_URL` 仅用于本地开发（直连 localhost）。

### 3.4 创建 Swap

Rust 编译占用 2-4 GB 内存，内存不足会 OOM（4 GB 以下 ECS 必做）：

```bash
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 3.5 构建并启动

```bash
cd /opt/virs

/* 构建镜像并启动（含隧道，首次需要 10-30 分钟编译 Rust） */
docker compose --profile tunnel up -d --build

/* 查看容器状态（应有 postgres + backend + cloudflared 三个） */
docker compose ps

/* 查看 cloudflared 隧道连接日志 */
docker compose logs -f cloudflared --tail 100
```

> 首次编译 10-30 分钟，后续增量编译 1-3 分钟。

### 3.6 配置 Cloudflare Tunnel

backend 绑定 `127.0.0.1:8080`，公网无法直达。通过 Cloudflare Tunnel 暴露为 HTTPS 域名 — 免费、零入站端口、自动证书，替代传统 Nginx + Certbot 方案。

> Tunnel 属于 Cloudflare Zero Trust 免费档，50 用户内零成本，不限连接数、不限流量。本项目仅单管理员，永久免费。

**步骤 1：创建隧道并获取 Token**

1. 登录 [Cloudflare Zero Trust](https://one.dash.cloudflare.com/) 控制台
2. Networks → Tunnels → Create a tunnel → 选 `Cloudflared` 类型
3. 命名隧道，创建后复制 **Tunnel Token**（形如 `eyJh...` 的长字符串）
4. 将 Token 填入 `.env`：`CLOUDFLARE_TUNNEL_TOKEN=eyJh...`

**步骤 2：配置 Public Hostname（回源路由）**

在隧道的 Public Hostname 页加一条：

| 字段 | 值 |
|------|------|
| Subdomain | `virs`（或任意子域名） |
| Domain | `你的域名.com`（须托管在 Cloudflare DNS） |
| Type | `HTTP` |
| URL | `backend:8080`（Docker 内网域名，**不是 localhost**） |

> cloudflared 与 backend 同在 `virs-net` Docker 网络，通过 Docker DNS 解析 `backend`。Cloudflare 边缘自动提供 443 HTTPS + 橙云代理 + DDoS 防护，DNS 的 CNAME 记录由隧道自动生成，无需手动配置。

**步骤 3：启动并验证隧道**

```bash
cd /opt/virs
docker compose --profile tunnel up -d
docker compose logs cloudflared | grep "Registered tunnel connection"
/* 看到 4 条 "Registered tunnel connection" 即隧道建立成功 */
```

访问 `https://virs.你的域名.com/` 即可。

### 3.7 验证部署

```bash
/* 1. 本地健康检查（应返回 ok） */
curl http://127.0.0.1:8080/api/health

/* 2. 公网访问（需先完成 3.6 隧道配置） */
/* https://virs.你的域名.com/ */

/* 3. 登录系统 */
/* 用户名：.env 里的 ADMIN_USERNAME */
/* 密码：.env 里的 ADMIN_PASSWORD */
```

## 4. 常用运维命令

```bash
cd /opt/virs

/* ---- 生命周期 ---- */
docker compose --profile tunnel up -d        /* 启动含隧道 */
docker compose --profile tunnel down         /* 停止含隧道 */
docker compose up -d                         /* 本地开发模式（无隧道） */

/* ---- 状态与日志 ---- */
docker compose ps
docker compose logs -f backend --tail 100
docker compose logs -f cloudflared           /* 隧道连接日志 */
docker compose restart cloudflared           /* 重启隧道客户端 */

/* ---- 升级 ---- */
docker compose --profile tunnel build backend && docker compose --profile tunnel up -d backend

/* ---- 数据库备份与恢复 ---- */
docker exec virs-postgres pg_dump -U virs virs > backup_$(date +%Y%m%d).sql
docker exec -i virs-postgres psql -U virs virs < backup_20260812.sql

/* ---- 清理 ---- */
docker compose --profile tunnel down         /* 停止所有服务 */
docker compose --profile tunnel down -v      /* 停止并删除数据卷（丢数据库） */
```

> 使用 `--profile tunnel` 时，`down` 也会停止 cloudflared。本地开发不带该参数即可。

## 5. 故障排查

### 5.1 容器启动失败

```bash
docker compose logs backend
docker compose logs postgres
```

常见错误：
- `ENCRYPTION_KEY is required` → `.env` 未配置
- `ADMIN_PASSWORD is required` → `.env` 未配置
- `ENCRYPTION_KEY must differ from LLM_KEY` → 两个密钥设成一样的了
- 数据库连接失败 → 检查 `POSTGRES_PASSWORD` 是否已修改（compose 自动拼接 `DATABASE_URL`，无需手动改）

### 5.2 cloudflared 隧道连不上 / 域名无法访问

```bash
docker compose logs cloudflared
```

常见错误：
- `error validating token` → `CLOUDFLARE_TUNNEL_TOKEN` 未填或填错
- 长时间无 `Registered tunnel connection` → ECS 出站被限，确认能出站到 TCP 7844/443
- 域名访问返回 502 → Public Hostname 的 URL 应填 `backend:8080`（Docker 内网），不是 localhost
- 域名访问返回 1033 → 隧道未连接，检查 cloudflared 是否在运行
- 容器列表没有 cloudflared → 启动时漏了 `--profile tunnel` 参数

### 5.3 本地能访问、公网不能访问

```bash
/* 1. 本地健康检查（应返回 ok） */
curl http://127.0.0.1:8080/api/health

/* 2. cloudflared 是否运行 */
docker compose ps cloudflared

/* 3. 隧道是否注册成功 */
docker compose logs cloudflared | grep "Registered tunnel connection"

/* 4. Cloudflare 控制台 Public Hostname 是否指向 backend:8080 */
```

### 5.4 构建时内存不足（OOM）

```bash
free -h
/* 创建 swap（见 3.4 节） */
/* 或限制 Rust 编译并行度：Dockerfile 中 cargo build 前加 ENV CARGO_BUILD_JOBS=1 */
```

### 5.5 前端构建失败

Dockerfile Stage 1 会执行 `npm run lint && npm run format:check`，代码质量不达标会阻断构建。本地修复后重新上传源码。

macOS `._*` 文件错误（打包时未加 `COPYFILE_DISABLE=1`）：

```bash
/* ECS 上清理 */
find /opt/virs -name "._*" -type f -delete
```

### 5.6 数据库迁移

迁移在 backend 启动时自动执行（`migrations/init.sql`），无需手动运行。查看数据库状态和表结构：

```bash
docker compose exec postgres pg_isready -U virs
docker exec -it virs-postgres psql -U virs -d virs -c "\dt"
```

## 6. 安全清单

部署前逐项确认：

- [ ] `ENCRYPTION_KEY`、`LLM_KEY`、`JWT_SECRET` 已改为强随机值
- [ ] `ADMIN_PASSWORD` 已改为强密码
- [ ] `POSTGRES_PASSWORD` 已改为强密码
- [ ] 安全组仅开放 22 端口（未开放 80/443/8080/5432）
- [ ] backend 与 postgres 端口均绑定 `127.0.0.1`（已由 docker-compose.yml 保证）
- [ ] `.env` 文件权限 `chmod 600`
- [ ] `CLOUDFLARE_TUNNEL_TOKEN` 已配置且隧道连接正常
- [ ] SSH 已禁用密码登录（仅用密钥）
- [ ] 已配置 swap（避免 OOM）
- [ ] 已配置日志轮转（docker-compose.yml 中已配置 `max-size=10m, max-file=3`）
- [ ] 已配置 PostgreSQL 定期备份

## 7. 资源占用参考

### 7.1 镜像大小

| 镜像 | 大小 |
|------|------|
| `virs-backend`（最终运行时镜像） | 约 50-80 MB |
| `postgres:16-alpine` | 约 80 MB |
| `cloudflare/cloudflared:latest` | 约 30-50 MB |
| 构建阶段临时镜像（不影响最终） | 约 2-3 GB |

### 7.2 运行时资源占用

| 资源 | 占用 |
|------|------|
| CPU 空闲 | < 1% |
| CPU 满载（交易密集） | 单核 50-80% |
| 内存 | 200-500 MB（backend）+ 100-200 MB（postgres）+ ~30 MB（cloudflared） |
| 磁盘 | 数据库数据增长，按交易量估算 |

### 7.3 推荐配置与成本

| 业务规模 | ECS 配置 | 月成本（估算） |
|---------|---------|---------------|
| 个人测试 | 2 核 2G + 40GB SSD | 约 ¥30-60 |
| 小规模实盘 | 2 核 4G + 40GB SSD | 约 ¥60-120 |
| 多策略运行 | 4 核 8G + 80GB SSD | 约 ¥150-300 |

> Cloudflare Tunnel 免费，不增加额外成本。

## 附录：一键部署脚本（可选）

> 以下脚本自动完成 Docker 安装、swap 创建、`.env` 检查、构建启动。**需先完成 3.2 上传源码到 `/opt/virs`**。

保存为 `deploy.sh`，在 ECS 上执行：

```bash
#!/bin/bash
set -e

DEPLOY_DIR="/opt/virs"

echo "===== VIRS 一键部署脚本 ====="

/* 1. 检查并安装 Docker */
if ! command -v docker &> /dev/null; then
    echo "安装 Docker..."
    curl -fsSL https://get.docker.com | sh
    systemctl enable --now docker
fi

/* 2. 创建 swap（内存 < 4G 时） */
if [ "$(free -g | awk '/^Mem:/{print $2}')" -lt 4 ]; then
    if ! swapon --show | grep -q swapfile; then
        echo "创建 4GB swap..."
        fallocate -l 4G /swapfile
        chmod 600 /swapfile
        mkswap /swapfile
        swapon /swapfile
        echo '/swapfile none swap sw 0 0' >> /etc/fstab
    fi
fi

/* 3. 检查 .env */
cd $DEPLOY_DIR
if [ ! -f .env ]; then
    install -m 600 .env.example .env
    echo "⚠️  请编辑 $DEPLOY_DIR/.env 配置密钥后再运行："
    echo "   nano $DEPLOY_DIR/.env"
    echo "   必填：ENCRYPTION_KEY, LLM_KEY, JWT_SECRET, ADMIN_PASSWORD"
    echo "   隧道：CLOUDFLARE_TUNNEL_TOKEN（见 3.6 节）"
    exit 1
fi

/* 4. 构建并启动（含 Cloudflare Tunnel） */
echo "开始构建（可能需要 10-30 分钟）..."
docker compose --profile tunnel up -d --build

/* 5. 健康检查（本地回环） */
echo "等待后端启动..."
sleep 10
if curl -s http://127.0.0.1:8080/api/health | grep -q "ok"; then
    echo "✅ 部署成功！"
    echo "   本地健康检查：http://127.0.0.1:8080/api/health"
    echo "   公网访问：请完成 Cloudflare Tunnel 配置后访问 https://你的域名/"
    echo "   隧道日志：docker compose logs cloudflared"
else
    echo "❌ 健康检查失败，查看日志："
    echo "   docker compose logs backend"
fi
```

使用方法：

```bash
chmod +x deploy.sh
./deploy.sh
```
